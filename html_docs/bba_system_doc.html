1. 构建预期现金流 (Construct Expected Cash Flows)

核心代码逻辑：BBA_dev/projector.py -> CashFlowProjector.project_policy_flows

基于全追溯法（Full Retrospective Approach, FRA），根据保单的基础信息和精算假设，按月投射未来的预期现金流。 这是BBA模型计算的基础输入。

1.1 输入数据 (Input Data)

数据来源 字段名 (Code) 描述 (Description)
保单数据 (Policy Data) premium 总保费 (不含税)
iacf_amount 初始获取成本 (IACF)
start_date 起保日期
end_date 终保日期
under_write_date 签单日期
warranty_end_date 厂家保修结束日期 (延保业务特有)
精算假设 (Assumptions) loss_ratio 赔付率假设
claim_expense_ratio 间接理赔费用率假设 (Applied to Claims)
maintenance_expense_ratio 维持费用率假设 (Applied to Earned Premium)

1.2 计算逻辑 (Calculation Logic)

1. 确定风险期间 (Risk Period)

风险期间是指保险公司实际承担风险的时间段。对于延保业务，风险通常在厂家保修期结束后开始。

Risk Start = warranty_end_date (若无则为 start_date)
Risk End = end_date
2. 计算月度满期保费 (Monthly Earned Premium)

将总保费平均分摊到风险期间的每个月。

Coverage Months = Months Between(Risk Start, Risk End) + 1
Monthly Earned = Premium / Coverage Months
3. 现金流投射 (Projection)

遍历从时间轴起点 (Timeline Start) 到终保日期 (End Date) 的每个月：

  • 保费 (Premium): 仅在签单月 (under_write_date) 发生。
    Premium Flow = premium (if current month == uw month) else 0
  • 获取成本 (IACF): 仅在签单月 (under_write_date) 发生。
    IACF Flow = iacf_amount (if current month == uw month) else 0
  • 赔付 (Claims): 仅在风险期间内发生。
    Claims Flow = Monthly Earned * loss_ratio * (1 + claim_expense_ratio)
  • 维持费用 (Expenses): 仅在风险期间内发生。
    Expenses Flow = Monthly Earned * maintenance_expense_ratio

1.3 输出字段 (Output Fields)

⚠️ 重要说明：现金流发生时点

为了简化计算，模型假设所有预期现金流均发生在月末 (End of Month)。 在折现计算时，需使用月末日期作为现金流发生日期。

字段名 (Field Name) 类型 (Type) 说明 (Description)
yyyymm String 现金流发生的年月 (格式：YYYYMM)
premium Float 预期保费流入 (Premium)
iacf Float 预期获取费用流出 (IACF)
claims Float 预期赔付流出 (Claims)
expenses Float 预期维持费用流出 (Maintenance Expenses)

2. 获取实际现金流 (Get Actual Cash Flows)

核心代码逻辑：BBA_dev/logic/actual_cashflows.py -> ActualCashflows

该步骤负责获取保单实际发生的现金流数据，主要包括实际保费 (Actual Premium) 和 实际获取成本 (Actual IACF)。 这些数据通常直接来源于业务系统或财务系统的实际记录。

2.1 输入数据 (Input Data)

数据来源 源字段名 (Source Field) 描述 (Description)
保单表 (t_pp_jl_contract) premium_cny 或 sum_premium_no_tax 实际签单保费 (不含税)
费用表 (summary_iacf_cost) iacf_amount 实际发生的初始获取成本
保单表 under_write_date 签单日期 (决定现金流归属年份)

2.2 处理逻辑 (Processing Logic)

1. 发生时间判定

模型假设实际现金流仅在签单年度 (Underwriting Year) 发生。

If Valuation Year == Underwriting Year: Return Actual Value
Else: Return 0
2. 数据加载优先权

系统支持两种加载模式：

  • 直接输入：如果在初始化时提供了数值，直接使用输入值。
  • 数据库加载：如果未提供数值，则通过 `data_loader` 从数据库读取。

2.3 输出字段 (Output Fields)

⚠️ 注意

实际现金流为名义金额 (Nominal Amount)，不包含任何利息成分。

字段名 (Field Name) 类型 (Type) 说明 (Description)
actual_premium Decimal 实际收到保费
actual_iacf Decimal 实际支付获取成本
occurrence_date Date 现金流发生日期 (通常为签单日期)

3. 现值 (PV) 计算 (Present Value Calculation)

核心代码逻辑：BBA_dev/pv_calculator.py -> calculate_pv_exact / calculate_pv_current_period_no_interest_after_occurrence

基于第1步生成的预期现金流，结合利率曲线，计算各时点的现值 (Present Value)。 这是BBA模型中最核心的计算环节，支撑后续所有负债计量。

3.1 计算类型 (Calculation Types)

针对不同的业务场景，系统采用了两种核心折现逻辑：

逻辑 A: 精确折现 (Precise Discounting)

适用场景：预期未来现金流 (Future Period Flows)。

逻辑描述：根据现金流发生日与评估日的时间差，选择对应的利率进行折现或终值累积。

  • 折现 (Discounting): 现金流在评估日之后 (CF Date > Val Date)。
    PV = Amount / [(1+r1) * (1+r2) * ... * (1+rn)]
  • 累积 (Accumulation): 现金流在评估日之前 (CF Date < Val Date)。
    PV = Amount * [(1+r1) * (1+r2) * ... * (1+rn)]
逻辑 B: 当期不计息 (No Interest for Current Period)

适用场景：预期当期现金流 (Current Period Flows) 滚动至期末。

逻辑描述：

  • 已发生 (Past): 如果现金流发生在评估月或之前，视为已发生，取原值，不计算利息。
  • 未发生 (Future): 如果现金流发生在评估月之后，按逻辑 A 进行折现。

主要用于计算 `Pvfl_Nb_Ini_Cca_Rep` (新增业务-初始确认-预期当期-期末现值) 等字段。

3.2 利率曲线选择 (Interest Rate Curves)

曲线类型 代码 (Code) 基准日 (Base Date) 适用场景
锁定曲线 (Locked Curve) Lkd / Wlk 签单日 (Underwriting Date) CSM 初始确认、后续计量、利息费用计算
当前曲线 (Current Curve) Cur 评估日 (Valuation Date) 履约现金流 (BEL) 重估、IFIE 计算
上年末锁定曲线 (Last Year Locked) Lcu 上年年末 (Last Year End) 年初现值计算 (用于分析变动)

4. 履约现金流变化 (Fulfillment Cashflow Changes)

核心代码逻辑：BBA_dev/logic/fulfillment_cashflow_changes.py

该步骤计算实际发生额与预期金额之间的差异（经验调整），以及假设变更带来的未来现金流现值变化。 这些变化将根据情况被 CSM (合同服务边际) 或 LC (亏损部分) 吸收，或直接计入当期损益。

4.1 经验调整 (Experience Adjustment)

经验调整反映了当期实际现金流与预期现金流之间的差异。

计算公式 (通用) 经验调整 = (期末预期 + 当期实际) - (初始/年初预期 + 当期预期) * 调整比例

4.1.1 保费现金流经验调整 (Premium Experience Adjustment)

  • 新增业务 (New Business): Adj_Prem = [(Nb_Eop_Cfa_Rep_Wlk_Pre + Nb_Actual_Pre) - (Nb_Ini_Cfa_Rep_Wlk_Pre + Nb_Ini_Cca_Rep_Wlk_Pre)] * Ratio
  • 有效业务 (In-force): Adj_Prem = [(If_Eop_Cfa_Rep_Wlk_Pre + If_Actual_Pre) - (If_Bop_Cfa_Rep_Wlk_Pre + If_Bop_Cca_Rep_Wlk_Pre)] * Ratio

4.1.2 IACF 经验调整 (IACF Experience Adjustment)

  • 新增业务 (New Business): Adj_IACF = [(Nb_Eop_Cfa_Rep_Wlk_Acq + Nb_Actual_Acq) - (Nb_Ini_Cfa_Rep_Wlk_Acq + Nb_Ini_Cca_Rep_Wlk_Acq)] * Ratio
  • 有效业务 (In-force): Adj_IACF = [(If_Eop_Cfa_Rep_Wlk_Acq + If_Actual_Acq) - (If_Bop_Cfa_Rep_Wlk_Acq + If_Bop_Cca_Rep_Wlk_Acq)] * Ratio

注：Ratio 为经验调整分摊比例，通常基于覆盖单元 (Coverage Units) 计算。 实际金额 (Actual) 为名义值，不计息。

4.2 被 CSM/LC 吸收的变化 (Changes Absorbed by CSM/LC)

这部分反映了由于精算假设变更（如退保率、费用率变化）导致的未来现金流现值的变化。 所有计算均使用锁定利率 (Locked Rate, Wlk)，以剔除金融假设变化的影响。

4.2.1 各项现金流变化明细

项目 (Item) 计算公式 (Formula) 说明 (Note)
保费变化
(Δ_Prem)		 (Pvfl_If_Eop_Cfa_Rep_Wlk_Pre + Pvfl_Nb_Eop_Cfa_Rep_Wlk_Pre)
- (Pvfl_If_Bop_Cfa_Rep_Wlk_Pre + Pvfl_Nb_Ini_Cfa_Rep_Wlk_Pre)
+ (If_Actual_Pre + Nb_Actual_Pre)
- (Pvfl_If_Bop_Cca_Rep_Wlk_Pre + Pvfl_Nb_Ini_Cca_Rep_Wlk_Pre)
- Adj_Prem 		扣除经验调整后的纯假设变更影响
IACF 变化
(Δ_IACF)		 (Pvfl_If_Eop_Cfa_Rep_Wlk_Acq + Pvfl_Nb_Eop_Cfa_Rep_Wlk_Acq)
- (Pvfl_If_Bop_Cfa_Rep_Wlk_Acq + Pvfl_Nb_Ini_Cfa_Rep_Wlk_Acq)
+ (If_Actual_Acq + Nb_Actual_Acq)
- (Pvfl_If_Bop_Cca_Rep_Wlk_Acq + Pvfl_Nb_Ini_Cca_Rep_Wlk_Acq)
- Adj_IACF 		同上
赔付变化
(Δ_Claims)		 (Pvfl_If_Eop_Cfa_Rep_Wlk_Cla + Pvfl_Nb_Eop_Cfa_Rep_Wlk_Cla)
- (Pvfl_If_Bop_Cfa_Rep_Wlk_Cla + Pvfl_Nb_Ini_Cfa_Rep_Wlk_Cla) 		仅涉及未来现金流现值的变动

(Δ_Maint)		 (Pvfl_If_Eop_Cfa_Rep_Wlk_Mtn + Pvfl_Nb_Eop_Cfa_Rep_Wlk_Mtn)
- (Pvfl_If_Bop_Cfa_Rep_Wlk_Mtn + Pvfl_Nb_Ini_Cfa_Rep_Wlk_Mtn) 		同上

4.2.2 汇总与吸收 (Aggregation & Absorption)

1. 预期现金流变化合计 (Total Expected CF Change)

汇总所有现金流成分的变化，注意符号方向（流入增加为正，流出增加为负）。

Δ_CF_Total = Δ_Prem - Δ_IACF - Δ_Claims - Δ_Maint
2. 非金融风险调整变化 (Δ_RA)

非金融风险调整 (Risk Adjustment) 的变动。

Δ_RA = (Pvfl_If_Eop_Cfa_Rep_Wlk_Rad + Pvfl_Nb_Eop_Cfa_Rep_Wlk_Rad) - (Pvfl_If_Bop_Cfa_Rep_Wlk_Rad + Pvfl_Nb_Ini_Cfa_Rep_Wlk_Rad)
3. 被 CSM/LC 吸收的变化合计 (Total Absorbed)

最终影响 CSM 或 LC 的总金额。

Δ_CSM/LC = Δ_CF_Total - Δ_RA

4.2.3 分摊逻辑 (Allocation Logic)

计算出的 Δ_CSM/LC 需要根据合同组当前的亏损状态 (Loss Component Ratio) 进行分摊：

  • 被 LC 吸收 (Absorbed by LC): Δ_CSM/LC * LC_Ratio
  • 被 CSM 吸收 (Absorbed by CSM): Δ_CSM/LC * (1 - LC_Ratio)

5. CSM/LC 计量 (CSM/LC Measurement)

核心代码逻辑：BBA_dev/logic/csm_lc_measurement.py

本步骤处理合同服务边际 (CSM) 和亏损成分 (LC) 的后续计量，包括计息、IFIE 分摊、合同组状态判定以及期末摊销。

5.1 CSM 计息 (CSM Interest Accretion)

使用加权锁定利率 (Weighted Locked Rate, Wlk) 计算 CSM 的利息增长。Wlk 曲线确定方式：若有 rate_locked_month 则取对应月的锁定曲线，否则取签单月 (UW Month) 的锁定曲线。

项目 (Item) 详细逻辑与公式 (Logic & Formula)
IF_年初CSM余额 直接取自输入数据（如 cohort_state.bop_csm，若>=0）。
当年新增合同CSM Max(0, PV_Prem - (PV_IACF + PV_Claims + PV_Maint) - PV_RA)
PV 数据来源 (PV Source Fields):
所有字段基于 Nb (新增业务) + Ini (初始确认视角) + Rec (初始确认时点) + Lkd (初始锁定利率)。
  • PV_Prem: Pvfl_Nb_Ini_Cca_Rec_Lkd_Pre_Amt + Pvfl_Nb_Ini_Cfa_Rec_Lkd_Pre_Amt
  • PV_IACF: Pvfl_Nb_Ini_Cca_Rec_Lkd_Acq_Amt + Pvfl_Nb_Ini_Cfa_Rec_Lkd_Acq_Amt
  • PV_Claims: Pvfl_Nb_Ini_Cca_Rec_Lkd_Cla_Amt + Pvfl_Nb_Ini_Cfa_Rec_Lkd_Cla_Amt
  • PV_Maint: Pvfl_Nb_Ini_Cca_Rec_Lkd_Mtn_Amt + Pvfl_Nb_Ini_Cfa_Rec_Lkd_Mtn_Amt
  • PV_RA: Pvfl_Nb_Ini_Cca_Rec_Lkd_Rad_Amt + Pvfl_Nb_Ini_Cfa_Rec_Lkd_Rad_Amt
说明: Cca (Current) 代表签单当年内的现金流，Cfa (Future) 代表签单当年以后的现金流。两者之和构成了该保单全生命周期的现金流现值。
期初有效合同CSM计息 Interest = IF_年初CSM余额 * Factor
通俗解释（原理）：
CSM 像一个银行账户，从“签单日”开始锁定利率并累积利息。我们要计算的是“今年这一年”（从年初到期末）产生了多少利息。
计算方法是：先算出从签单日持有到“期末”的总本息倍数，再除以从签单日持有到“年初”的总本息倍数，得到的差额就是今年的利率。

举例说明：
  • 签单日 (T_UW): 2022年1月1日
  • 年初 (T_Start): 2023年1月1日（距签单12个月）
  • 期末 (T_End): 2023年12月31日（距签单24个月）
  • 查锁定曲线：
    • 第12个月的累积因子 (Rate_Start_Acc) = 1.03 (即累积增长3%)
    • 第24个月的累积因子 (Rate_End_Acc) = 1.0609 (即累积增长6.09%)
  • 计算 Factor： 1.0609 / 1.03 - 1 = 0.03 (3%)
  • 结论： 今年的利息 = 年初余额 × 3%

详细公式：
1. Term_Start = (年初日期 - 签单日期) 的月数。
2. Term_End = (评估日期 - 签单日期) 的月数。
3. Factor = (1 + Rate_End_Acc) / (1 + Rate_Start_Acc) - 1。
注：Rate_Acc 指从签单日开始累积到该期限的复利因子。
新增合同CSM计息 Interest = 当年新增合同CSM * Factor
Factor 计算：
1. Start_Term = 1 (初始确认时), End_Term = (UW_Date 到 评估期末) 的月数。
2. 查 Wlk 曲线计算 Factor，逻辑同上。
IF_计息后CSM IF_年初CSM余额 + 期初有效合同CSM计息
NB_计息后CSM 当年新增合同CSM + 新增合同CSM计息

5.2 LC 分摊 IFIE (LC IFIE Allocation)

计算归属于亏损成分 (LC) 的保险财务收益或费用 (IFIE)。逻辑核心：LC 承担部分利息费用和利率变动损益。

5.2.1 有效业务 (In-force)

项目详细逻辑与公式
IF_年初LC 取自输入数据 cohort_state.bop_csm（若<0 取绝对值）。
IF_LC IFIE分摊比例 Ratio = |IF_年初LC| / Denom
分母 (Denom)： Pvfl_If_Bop_Cfa_Beg_Lcu_{Cla+Mtn+Rad} + Pvfl_If_Bop_Cca_Beg_Lcu_{Cla+Mtn+Rad}
含义：年初时刻，基于上年末锁定利率 (Lcu) 计算的未来现金流现值总和。
IF_待分摊IFIE_计息_赔付与费用 (Pvfl_If_Bop_Cfa_Rep_Wlk_{Cla+Mtn} + Pvfl_If_Bop_Cca_Rep_Wlk_{Cla+Mtn}) - (Pvfl_If_Bop_Cfa_Beg_Wlk_{Cla+Mtn})
含义：期末Wlk现值 - 年初Wlk现值（纯利息累积部分）。
IF_待分摊IFIE_计息_非金融风险调整 (Pvfl_If_Bop_Cfa_Rep_Wlk_Rad + Pvfl_If_Bop_Cca_Rep_Wlk_Rad) - (Pvfl_If_Bop_Cfa_Beg_Wlk_Rad)
IF_待分摊IFIE_利率变化的影响_赔付与费用 Term_End_Diff - Term_Beg_Diff
Term_End_Diff = Pvfl_If_Eop_Cfa_Rep_Cur_{Cla+Mtn} - Pvfl_If_Eop_Cfa_Rep_Wlk_{Cla+Mtn}
Term_Beg_Diff = Pvfl_If_Bop_Cfa_Beg_Lcu_{Cla+Mtn} - Pvfl_If_Bop_Cfa_Beg_Wlk_{Cla+Mtn}
含义：期末利率差 - 年初利率差。
IF_待分摊IFIE_利率变化的影响_非金融风险调整 同上，将后缀 {Cla+Mtn} 替换为 Rad。
IF_LC分摊IFIE_赔付与费用 (IF_待分摊IFIE_计息_赔付与费用 + IF_待分摊IFIE_利率变化的影响_赔付与费用) * IF_LC IFIE分摊比例
IF_LC分摊IFIE_非金融风险调整 (IF_待分摊IFIE_计息_非金融风险调整 + IF_待分摊IFIE_利率变化的影响_非金融风险调整) * IF_LC IFIE分摊比例
IF_LC分摊IFIE 上述两项之和。
IF_分摊后IFIE后LC IF_年初LC + IF_LC分摊IFIE（注意符号：LC通常为负值，IFIE为损益影响）。

5.2.2 新增业务 (New Business)

项目详细逻辑与公式
NB_新增LC 取自初始确认结果 nb_initial_lc（若<0 取绝对值，通常记录为负数）。
NB_LC IFIE分摊比例 Ratio = |NB_新增LC| / Denom
分母 (Denom)： Pvfl_Nb_Ini_Cfa_Rec_Lkd_{Cla+Mtn+Rad}
含义：初始确认时刻，基于当月初始利率 (Lkd) 计算的未来现金流现值总和。
NB_待分摊IFIE_计息_赔付与费用 (Pvfl_Nb_Ini_Cfa_Rep_Wlk_{Cla+Mtn} + Pvfl_Nb_Ini_Cca_Rep_Wlk_{Cla+Mtn}) - (Pvfl_Nb_Ini_Cfa_Rec_Lkd_{Cla+Mtn})
含义：期末Wlk现值 - 初始Lkd现值（注意：初始Lkd即为Wlk起点）。
NB_待分摊IFIE_计息_非金融风险调整 同上，将后缀 {Cla+Mtn} 替换为 Rad。
NB_待分摊IFIE_利率变化的影响_赔付与费用 Pvfl_Nb_Eop_Cfa_Rep_Cur_{Cla+Mtn} - Pvfl_Nb_Eop_Cfa_Rep_Wlk_{Cla+Mtn}
含义：新增业务仅计算期末时刻的利率差（初始时刻Cur=Lkd，差额为0）。
NB_待分摊IFIE_利率变化的影响_非金融风险调整 同上，将后缀 {Cla+Mtn} 替换为 Rad。
NB_LC分摊IFIE_赔付与费用 (NB_待分摊IFIE_计息_赔付与费用 + NB_待分摊IFIE_利率变化的影响_赔付与费用) * NB_LC IFIE分摊比例
NB_LC分摊IFIE_非金融风险调整 (NB_待分摊IFIE_计息_非金融风险调整 + NB_待分摊IFIE_利率变化的影响_非金融风险调整) * NB_LC IFIE分摊比例
NB_LC分摊IFIE 上述两项之和。
NB_分摊后IFIE后LC NB_新增LC + NB_LC分摊IFIE。

5.3 合同组 CSM/LC 判断 (Cohort Status Determination)

净余额试算 (Net Trial Balance)

公式： Net_Trial = IF_计息后CSM + NB_计息后CSM + IF_分摊后IFIE后LC + NB_分摊后IFIE后LC
说明： 此时汇总了期初余额、新增业务、利息累积和 IFIE 分摊，尚未包含当期履约现金流的变化（经验调整和假设变更）。

判定结果详细逻辑
合同组CSM IF Net_Trial >= 0 THEN Cohort_CSM = Net_Trial ELSE 0
若为正，表示合同组当前处于盈利状态。
合同组LC IF Net_Trial < 0 THEN Cohort_LC = Net_Trial ELSE 0
若为负，表示合同组当前处于亏损状态。

11. 合同组CSM/LC计量 (Group CSM/LC Measurement)

11.1 CSM计息（组级口径）

输入与利率
  • 组级期初IF CSM余额：上一年度末仍在服务期的CSM之和。
  • 组级当年新增CSM：本年度新签且 margin≥0 的初始CSM之和，基于签单月初始折现因子。
  • 组级锁定利率：由 group_rates_manager 计算的加权锁定利率，可拆分为月度利率 r_m。

11.1.1 期初有效合同CSM计息（按月滚动，组级）

  • 1月：IF_interest_Jan = CSM_IF_BOP_group × r_Jan
  • 2-12月：
    • 若上月CSM摊销比例=100%，本月不再新增计息（可视为0或沿用上月结果，仅做展示）。
    • 否则：从年初1月到当前评估月m，按组级锁定利率累乘得到年度有效利率 R_1..m，本年度IF计息为：
      IF_interest_1..m = CSM_IF_BOP_group × ((1+R_1..m) - 1)，其中 R_1..m 由1月至m月的月利率逐月复利得到。

11.1.2 当年新增合同CSM计息（按签单月起息，组级）

  • 1月新增：新增CSM在月中确认，首月计息用半月复利：
    NB_interest_Jan = New_CSM_Jan × ((1 + r_Jan/2) - 1) （等价于 (1+r_Jan)^{0.5}-1）。
  • 2-12月：
    • 若上月CSM摊销比例=100%，当月不再新增计息。
    • 否则拆两块：
      • 当月新签（当期评估月，CSM>0）：首月计半个月利息：CSM_new_m × ((1+r_m/2) - 1)。
      • 本年已签但未摊完（当年早期签单的NB存量）：直接用“初始确认CSM本金 × 累乘因子差分”计算本月利息，无需上月末本息：
        NB_interest_on_prior(m) = NB_initial_CSM × (AccFactor(UW→当月末) - AccFactor(UW→上月末))
        AccFactor：首月用 (1+r_UW/2)，之后每月乘 (1+r_k) 逐月累乘。

11.1.3 计息后CSM（组级）

  • IF_计息后CSM(组) = IF_年初CSM余额(组) + 当期IF CSM计息(组)
  • NB_计息后CSM(组) = 当年新增合同CSM(组) + 当期NB CSM计息(组)

NB_LC分摊IFIE_赔付与费用 (NB_待分摊IFIE_计息_赔付与费用(组) + NB_待分摊IFIE_利率变化的影响_赔付与费用(组)) × NB_LC IFIE分摊比例(组)

注意：使用组级分摊比例。
NB_LC分摊IFIE_非金融风险调整 (NB_待分摊IFIE_计息_非金融风险调整(组) + NB_待分摊IFIE_利率变化的影响_非金融风险调整(组)) × NB_LC IFIE分摊比例(组)
NB_LC分摊IFIE NB_LC分摊IFIE_赔付与费用(组) + NB_LC分摊IFIE_非金融风险调整(组)
NB_分摊后IFIE后LC NB_新增LC(组) + NB_LC分摊IFIE(组)

11.3 合同组CSM/LC判断（组级口径）

在完成CSM计息和LC分摊IFIE后，需要判断合同组整体是处于盈利状态（CSM）还是亏损状态（LC）。

净余额试算（Net Trial Balance）

汇总所有计息和IFIE分摊后的余额：

Net_Trial = IF_计息后CSM(组) + NB_计息后CSM(组) + IF_分摊后IFIE后LC(组) + NB_分摊后IFIE后LC(组)

说明：此时汇总了期初余额、新增业务、利息累积和IFIE分摊，尚未包含当期履约现金流的变化（经验调整和假设变更）。

项目 组级计算逻辑
合同组CSM

若 Net_Trial >= 0：

合同组CSM = Net_Trial = IF_计息后CSM(组) + NB_计息后CSM(组) + IF_分摊后IFIE后LC(组) + NB_分摊后IFIE后LC(组)

若 Net_Trial < 0：

合同组CSM = 0

含义：若净余额为正或零，表示合同组当前处于盈利状态，全部余额计入CSM。
合同组LC

若 Net_Trial < 0：

合同组LC = Net_Trial = IF_计息后CSM(组) + NB_计息后CSM(组) + IF_分摊后IFIE后LC(组) + NB_分摊后IFIE后LC(组)

若 Net_Trial >= 0：

合同组LC = 0

含义：若净余额为负，表示合同组当前处于亏损状态，全部余额计入LC（通常为负值）。
⚠️ 重要说明

互斥性：合同组CSM和合同组LC是互斥的，同一时点只能有一个非零值。
后续处理：在后续步骤（被CSM/LC吸收、摊销、期末结转）中，将根据合同组CSM/LC的判断结果，决定变化是被CSM吸收还是被LC吸收。

11.4 CSM计量（组级口径）

计算合同组CSM的摊销和期末余额。核心是确定有多少"履约现金流变化"被CSM吸收，以及按组级覆盖单元比例进行摊销。

项目 组级计算逻辑
CSM摊销比例

组级计算方式：合同组内所有保单的分子汇总、分母汇总后再计算比例。

CSM摊销比例(组) = Σ[CU_released(单保单)] / Σ[CU_released(单保单) + CU_remaining(单保单)]

说明：不能先算单保单比例再平均，必须分别汇总分子和分母后再计算。
年初CSM余额 IF_年初CSM余额(组)
当年新增CSM NB_新增CSM(组)（汇总当年各月新增合同中CSM≥0的值）
CSM计息 IF_CSM计息(组) + NB_CSM计息(组)
被CSM吸收的变化

复杂条件判断：

若满足以下任一条件：

  • (合同组CSM > 0) AND (合同组CSM + 被CSM/LC吸收的变化合计 >= 0)，或
  • (合同组CSM = 0) AND (合同组LC + 分摊的LC_合计 + 被CSM/LC吸收的变化合计 >= 0)

则：

被CSM吸收的变化(组) = 被CSM/LC吸收的变化合计(组) + 年初LC余额_合计(组) + 当年新增LC_合计(组) + LC分摊IFIE_合计(组) + 分摊的LC_合计(组)

否则：

被CSM吸收的变化(组) = -(年初CSM余额(组) + 当年新增CSM(组) + CSM计息(组))

含义：若变化后仍为盈利或转为盈利，则全部变化被CSM吸收；否则，仅吸收至CSM归零。
被CSM吸收的现金流变化 被CSM吸收的现金流变化(组) = 预期现金流变化合计(组) - 被LC吸收的变化_预期现金流(组)
被CSM吸收的非金融风险调整变化 被CSM吸收的非金融风险调整变化(组) = 非金融风险调整变化(组) - 被LC吸收的变化_非金融风险调整(组)
摊销的CSM CSM_Before_Amort(组) = 年初CSM余额(组) + 当年新增CSM(组) + CSM计息(组) + 被CSM吸收的变化(组)
IF CSM_Before_Amort(组) <= 0 THEN 0
ELSE 摊销的CSM(组) = -CSM_Before_Amort(组) × CSM摊销比例(组)

说明：负号表示减少负债（增加收入）。
期末CSM余额 期末CSM余额(组) = 年初CSM余额(组) + 当年新增CSM(组) + CSM计息(组) + 被CSM吸收的变化(组) + 摊销的CSM(组)

11.5 LC计量（组级口径）

计算期末LC余额，需考虑当期履约现金流变化中被LC吸收的部分。分为三个维度分别计算：预期现金流、非金融风险调整和合计。

11.5.1 预期现金流部分

项目 组级计算逻辑
年初LC余额_预期现金流 直接取数：IF_年初LC_预期现金流(组)
当年新增LC_预期现金流 当年新增LC_预期现金流(组) = 当年新增LC_合计(组) × Ratio_CF

Ratio_CF计算：

Ratio_CF = (Σ[新增合同_预期赔付现金流_初始确认现值] + Σ[新增合同_预期维持费用现金流_初始确认现值]) / (Σ[新增合同_预期赔付现金流_初始确认现值] + Σ[新增合同_预期维持费用现金流_初始确认现值] + Σ[新增合同_预期非金融风险调整_初始确认现值])

说明：若分母为0，则返回0。
LC分摊IFIE_预期现金流 IF_LC分摊IFIE_赔付与费用(组) + NB_LC分摊IFIE_赔付与费用(组)
分摊的LC_预期现金流 分摊的LC_预期现金流(组) = -(PV_If_Cur_Claims + PV_If_Cur_Maint + PV_Nb_Cur_Claims + PV_Nb_Cur_Maint) × LC分摊比例(组)

PV字段说明：

  • PV_If_Cur_Claims：有效合同-年初预期-预期当年-赔付现金流-期末现值（加权初始确认利率）
  • PV_If_Cur_Maint：有效合同-年初预期-预期当年-维持费用现金流-期末现值（加权初始确认利率）
  • PV_Nb_Cur_Claims：新增合同-初始确认-预期当期-赔付现金流-期末现值（加权初始确认利率）
  • PV_Nb_Cur_Maint：新增合同-初始确认-预期当期-维持费用现金流-期末现值（加权初始确认利率）
被LC吸收的变化_预期现金流

若 待调整LC余额_合计 = 0：

被LC吸收的变化_预期现金流(组) = -(年初LC余额_合计(组) + 当年新增LC_合计(组) + LC分摊IFIE_合计(组) + 分摊的LC_合计(组))

否则：

被LC吸收的变化_预期现金流(组) = 被LC吸收的变化_合计(组) × (预期现金流变化合计(组) / 被CSM/LC吸收的变化合计(组))

说明：若分母为0，则返回0。
待调整LC余额_预期现金流 待调整LC余额_预期现金流(组) = 年初LC余额_预期现金流(组) + 当年新增LC_预期现金流(组) + LC分摊IFIE_预期现金流(组) + 分摊的LC_预期现金流(组) + 被LC吸收的变化_预期现金流(组)
LC调整_预期现金流

若 CSM摊销比例 = 100%：

LC调整_预期现金流(组) = -待调整LC余额_预期现金流(组)

否则：

LC调整_预期现金流(组) = 0
期末LC余额_预期现金流 期末LC余额_预期现金流(组) = 待调整LC余额_预期现金流(组) + LC调整_预期现金流(组)

11.5.2 非金融风险调整部分

项目 组级计算逻辑
年初LC余额_非金融风险调整 直接取数：IF_年初LC_非金融风险调整(组)
当年新增LC_非金融风险调整 当年新增LC_合计(组) - 当年新增LC_预期现金流(组)
LC分摊IFIE_非金融风险调整 IF_LC分摊IFIE_非金融风险调整(组) + NB_LC分摊IFIE_非金融风险调整(组)
分摊的LC_非金融风险调整 分摊的LC_非金融风险调整(组) = -(PV_If_Cur_RA + PV_Nb_Cur_RA) × LC分摊比例(组)

PV字段说明：

  • PV_If_Cur_RA：有效合同-年初预期-预期当年-非金融风险调整-期末现值（加权初始确认利率）
  • PV_Nb_Cur_RA：新增合同-初始确认-预期当期-非金融风险调整-期末现值（加权初始确认利率）
被LC吸收的变化_非金融风险调整 被LC吸收的变化_合计(组) - 被LC吸收的变化_预期现金流(组)
待调整LC余额_非金融风险调整 待调整LC余额_非金融风险调整(组) = 年初LC余额_非金融风险调整(组) + 当年新增LC_非金融风险调整(组) + LC分摊IFIE_非金融风险调整(组) + 分摊的LC_非金融风险调整(组) + 被LC吸收的变化_非金融风险调整(组)
LC调整_非金融风险调整

若 CSM摊销比例 = 100%：

LC调整_非金融风险调整(组) = -待调整LC余额_非金融风险调整(组)

否则：

LC调整_非金融风险调整(组) = 0
期末LC余额_非金融风险调整 期末LC余额_非金融风险调整(组) = 待调整LC余额_非金融风险调整(组) + LC调整_非金融风险调整(组)

11.5.3 合计部分

项目 组级计算逻辑
LC分摊比例_合计

若 合同组LC < 0：

LC分摊比例_合计(组) = |合同组LC(组)| / Denom(组)

分母（组级汇总）：

Denom(组) = Σ[IF_预期赔付现金流(上年12月期末值)] + Σ[当年NB各月汇总预期赔付现金流] + Σ[IF_预期维持费用现金流(上年12月期末值)] + Σ[当年NB各月汇总预期维持费用现金流] + Σ[IF_预期非金融风险调整(上年12月期末值)] + Σ[当年NB各月汇总预期非金融风险调整] + Σ[IF_待分摊IFIE_计息_赔付与费用] + Σ[NB_待分摊IFIE_计息_赔付与费用] + Σ[IF_待分摊IFIE_计息_非金融风险调整] + Σ[NB_待分摊IFIE_计息_非金融风险调整] + Σ[IF_待分摊IFIE_利率变化的影响_赔付与费用] + Σ[NB_待分摊IFIE_利率变化的影响_赔付与费用] + Σ[IF_待分摊IFIE_利率变化的影响_非金融风险调整] + Σ[NB_待分摊IFIE_利率变化的影响_非金融风险调整]

否则：LC分摊比例_合计(组) = 0
年初LC余额_合计 IF_年初LC(组)
当年新增LC_合计 NB_新增LC(组)
LC分摊IFIE_合计 IF_LC分摊IFIE(组) + NB_LC分摊IFIE(组)
分摊的LC_合计 分摊的LC_合计(组) = -(PV_If_Cur_Claims + PV_If_Cur_Maint + PV_If_Cur_RA + PV_Nb_Cur_Claims + PV_Nb_Cur_Maint + PV_Nb_Cur_RA) × LC分摊比例(组)

说明：包含预期现金流和非金融风险调整两部分。
被LC吸收的变化_合计

复杂条件判断：

若满足以下任一条件：

  • (合同组LC < 0) AND (合同组LC + 分摊的LC_合计 + 被CSM/LC吸收的变化合计 < 0)，或
  • (合同组LC = 0) AND (合同组CSM + 被CSM/LC吸收的变化合计 < 0)

则：

被LC吸收的变化_合计(组) = 被CSM/LC吸收的变化合计(组) + 年初CSM余额(组) + 当年新增CSM(组) + CSM计息(组)

否则：

被LC吸收的变化_合计(组) = -(年初LC余额_合计(组) + 当年新增LC_合计(组) + LC分摊IFIE_合计(组) + 分摊的LC_合计(组))

含义：若变化后仍为亏损或转为亏损，则全部变化被LC吸收；否则，仅吸收至LC归零。
待调整LC余额_合计 待调整LC余额_合计(组) = 年初LC余额_合计(组) + 当年新增LC_合计(组) + LC分摊IFIE_合计(组) + 分摊的LC_合计(组) + 被LC吸收的变化_合计(组)
LC调整_合计

若 CSM摊销比例 = 100%：

LC调整_合计(组) = -待调整LC余额_合计(组)

否则：

LC调整_合计(组) = 0
期末LC余额_合计 期末LC余额_合计(组) = 待调整LC余额_合计(组) + LC调整_合计(组)

后续步骤（被CSM/LC吸收、摊销、期末结转）可在组级层面套用单保单同款公式，使用组级覆盖单元比例与组级LC分摊比例。
