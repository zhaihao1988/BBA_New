# 经验调整计量方案详解

## 1. 概述

经验调整（Experience Adjustment）是BBA计量体系中的核心环节，用于反映实际经验与初始预期之间的差异。根据IFRS 17准则，经验调整需要区分与**过去/当前服务相关**和与**未来服务相关**的部分，前者直接计入当期损益，后者调整CSM/LC。

本项目中的经验调整主要涉及两个方面：
1. **保费现金流经验调整**（文档第4.3节）
2. **IACF经验调整**（文档第4.4节）

---

## 2. 基本概念与记号定义

### 2.1 合同类型区分

- **Eff**：年初有效合同（存量合同）
- **New**：当年新增合同

**重要说明**：实施时需先判定合同类型。若当前记录为新增合同，仅取 `New.*` 相关项；若为存量合同，则仅取 `Eff.*` 相关项。

### 2.2 现值记号定义

以下记号在保费与IACF公式中共用：

| 记号 | 含义 | 说明 |
|------|------|------|
| `F_end` | 期末预期-预期未来-期末现值 | 使用**加权初始确认利率**折现 |
| `F_beg` | 年初预期-预期未来-期末现值 | 使用**加权初始确认利率**折现 |
| `F_init` | 新增合同-初始确认-预期未来-期末现值 | 使用**加权初始确认利率**折现 |
| `C_actual` | 当年实际现金流 | 实际发生的现金流（名义值） |
| `C_year` | 年初预期-预期当年-期末现值 | 使用**加权初始确认利率**折现 |
| `C_init` | 新增合同-初始确认-预期当期-期末现值 | 使用**加权初始确认利率**折现 |

**关键要求**：所有 "F"/"C" 项需保持**同一加权初始确认利率**，确保计算口径一致。

### 2.3 经验调整占比

- **EA_ratio_prem**：保费现金流与过去/当前服务相关的经验调整占比（默认值：**100%**）
- **EA_ratio_iacf**：IACF与过去/当前服务相关的经验调整占比（默认值：**0%**）

## 3. 保费现金流经验调整（Sec 4.3）

### 3.1 新增合同公式

#### 公式

```
Adj_Prem^New = [(New.F_end + New.C_actual) - (New.F_init + New.C_init)] × EA_ratio_prem
```

#### 详细展开

```
Adj_Prem^New = [
    (New.F_end + New.C_actual) - 
    (New.F_init + New.C_init)
] × EA_ratio_prem
```

其中：
- **New.F_end**：新增合同-期末预期-预期未来-期末现值-加权初始确认利率-保费现金流
  - PV字段：`Pvfl_Nb_Eop_Cfa_Rep_Wlk_Pre_Amt`
  - 含义：期末时点，对新增合同未来保费的预期现值（使用加权初始确认利率折现）
  
- **New.C_actual**：新增合同当年实际保费现金流
  - 签单年度：`New.C_actual = 签单保费`（实际值）
  - 签单年度之后：`New.C_actual = 0`（一次性缴费，后续无保费）
  
- **New.F_init**：新增合同-初始确认-预期未来-期末现值-加权初始确认利率-保费现金流
  - PV字段：`Pvfl_Nb_Ini_Cfa_Rep_Wlk_Pre_Amt`
  - 含义：初始确认时，对新增合同未来保费的预期现值（使用加权初始确认利率折现）
  
- **New.C_init**：新增合同-初始确认-预期当期-期末现值-加权初始确认利率-保费现金流
  - PV字段：`Pvfl_Nb_Ini_Cca_Rep_Wlk_Pre_Amt`
  - 含义：初始确认时，对新增合同当期保费的预期现值（使用加权初始确认利率折现）

- **EA_ratio_prem**：保费经验调整占比（默认：**100%**）

#### 中文解释

**新增合同的保费现金流经验调整**反映的是：
- **期末实际状态**：`(New.F_end + New.C_actual)` 表示期末时点，新增合同的实际保费收入（包括已收到的实际保费和期末对未来保费的预期现值）
- **初始预期状态**：`(New.F_init + New.C_init)` 表示初始确认时，对新增合同保费的预期（包括预期当期保费和预期未来保费）
- **差异**：两者之差即为实际与预期的差异
- **调整占比**：乘以 `EA_ratio_prem`（默认100%）后，得到最终的经验调整金额

**业务含义**：
- 正值：实际收到的保费（或期末对未来的预期）高于初始预期，属于有利差异
- 负值：实际收到的保费（或期末对未来的预期）低于初始预期，属于不利差异
- 零值：实际与预期完全一致

#### 实施要点

1. **一次性缴费场景**：
   - 签单年度：`New.C_actual = 签单保费`（实际值）
   - 签单年度之后：`New.C_actual = 0`，且所有预期未来保费均为0，因此经验调整通常为0

2. **数据来源**：
   - 所有现值项（`F_end`、`F_init`、`C_init`）必须从**PV原材料数据**中读取
   - 实际保费（`C_actual`）从数据库保单数据中读取
   - 不允许使用旧的计算方式

3. **利率一致性**：
   - 所有现值项必须使用**同一加权初始确认利率**（`Wlk`），确保计算口径一致

### 3.2 存量合同公式

#### 公式

```
Adj_Prem^Eff = [(Eff.F_end + Eff.C_actual) - (Eff.F_beg + Eff.C_year)] × EA_ratio_prem
```

  - 含义：年初时点，对有效合同未来保费的预期现值（使用加权初始确认利率折现）

- **EA_ratio_prem**：保费经验调整占比（默认：**100%**）

#### 中文解释

**存量合同的保费现金流经验调整**反映的是：

## 4. IACF经验调整（Sec 4.4）

IACF（Insurance Acquisition Cash Flows，保险获取现金流）经验调整使用与保费现金流相同的拆分思路，变量全部换成IACF对应值（记作上标 `I`）。

### 4.1 新增合同公式

#### 公式

```
Adj_IACF^New = [(New.F_end^I + New.C_actual^I) - (New.F_init^I + New.C_init^I)] × EA_ratio_iacf
```

#### 详细展开

```
Adj_IACF^New = [
    (New.F_end^I + New.C_actual^I) - 
    (New.F_init^I + New.C_init^I)
] × EA_ratio_iacf
```

其中：
- **New.F_end^I**：新增合同-期末预期-预期未来-期末现值-加权初始确认利率-保险获取现金流
  - PV字段：`Pvfl_Nb_Eop_Cfa_Rep_Wlk_Acq_Amt`
  - 含义：期末时点，对新增合同未来IACF的预期现值（使用加权初始确认利率折现）
  
- **New.C_actual^I**：新增合同当年实际IACF现金流
  - 签单年度：从PV原材料数据读取实际获取费用
    - PV字段：`Pvfl_Nb_Ini_Cca_Rec_Lkd_Acq_Amt`
    - 含义：签单时点发生的IACF，现值=名义值（不折现）
  - 签单年度之后：`New.C_actual^I = 0`（后续年度无实际IACF现金流）
  
- **New.F_init^I**：新增合同-初始确认-预期未来-期末现值-加权初始确认利率-保险获取现金流
  - PV字段：`Pvfl_Nb_Ini_Cfa_Rep_Wlk_Acq_Amt`
  - 含义：初始确认时，对新增合同未来IACF的预期现值（使用加权初始确认利率折现）
  
- **New.C_init^I**：新增合同-初始确认-预期当期-期末现值-加权初始确认利率-保险获取现金流
  - PV字段：`Pvfl_Nb_Ini_Cca_Rep_Wlk_Acq_Amt`
  - 含义：初始确认时，对新增合同当期IACF的预期现值（使用加权初始确认利率折现）

- **EA_ratio_iacf**：IACF经验调整占比（默认：**0%**）

#### 中文解释

**新增合同的IACF经验调整**反映的是：
- **期末实际状态**：`(New.F_end^I + New.C_actual^I)` 表示期末时点，新增合同的实际IACF支出（包括已支付的实际IACF和期末对未来IACF的预期现值）
- **初始预期状态**：`(New.F_init^I + New.C_init^I)` 表示初始确认时，对新增合同IACF的预期（包括预期当期IACF和预期未来IACF）
- **差异**：两者之差即为实际与预期的差异
- **调整占比**：乘以 `EA_ratio_iacf`（默认0%）后，得到最终的经验调整金额

**业务含义**：
- 由于默认 `EA_ratio_iacf = 0%`，IACF经验调整通常为0
- 如果实际IACF与预期存在差异，该差异不会通过经验调整反映，而是通过其他机制（如IACF摊销）处理

#### 实施要点

1. **一次性缴费场景**：
   - 签单年度：`New.C_actual^I = 实际获取费用`（从PV数据读取）
   - 签单年度之后：`New.C_actual^I = 0`，且所有预期未来IACF均为0

2. **数据来源**：
   - 所有现值项（`F_end^I`、`F_init^I`、`C_init^I`）必须从**PV原材料数据**中读取
   - 实际IACF（`C_actual^I`）在签单年度从PV数据读取，签单年度之后为0

3. **利率一致性**：
   - 所有现值项必须使用**同一加权初始确认利率**（`Wlk`）

## 5. 经验调整合计

### 5.1 公式

```
Adj_Total = Adj_Prem + Adj_IACF
```

其中：
- `Adj_Prem`：保费现金流经验调整（根据合同类型取 `Adj_Prem^New` 或 `Adj_Prem^Eff`）
- `Adj_IACF`：IACF经验调整（根据合同类型取 `Adj_IACF^New` 或 `Adj_IACF^Eff`）

### 5.2 中文解释

**经验调整合计**是保费现金流经验调整和IACF经验调整的加总，反映实际经验与预期差异对保险合同计量的综合影响。

## 6. 实施要点总结

### 6.1 数据来源要求

1. **PV原材料数据**：
   - 所有现值项（`F_end`、`F_beg`、`F_init`、`C_year`、`C_init`等）必须从**PV原材料数据**中读取
   - PV原材料数据由 `pv_calculator.py` 生成，存储在 `logs/pv_source_data_{policy_no}.json`
   - **不允许使用旧的计算方式**

2. **实际现金流数据**：
   - 实际保费（`C_actual`）从数据库保单数据中读取
   - 实际IACF（`C_actual^I`）在签单年度从PV数据读取，签单年度之后为0

### 6.2 利率一致性要求

- 所有现值项必须使用**同一加权初始确认利率**（`Wlk`）
- 确保计算口径一致，避免因利率不一致导致的计量偏差

### 6.3 合同类型判定

- 实施时需先判定合同类型：
  - 若当前记录为**新增合同**，仅取 `New.*` 相关项
  - 若为**存量合同**，仅取 `Eff.*` 相关项
- 不允许同时使用两种类型的项

### 6.4 一次性缴费场景处理

- **新增合同（签单年度）**：
  - `New.C_actual = 签单保费`（实际值）
  - `New.C_actual^I = 实际获取费用`（从PV数据读取）
  
- **新增合同（签单年度之后）**：
  - `New.C_actual = 0`
  - `New.C_actual^I = 0`
  - 所有预期未来保费和IACF均为0，经验调整通常为0

- **存量合同（后续年度）**：
  - `Eff.C_actual = 0`
  - `Eff.C_actual^I = 0`
  - 所有预期未来保费和IACF均为0，经验调整通常为0

### 6.5 经验调整占比

- **EA_ratio_prem**：默认 **100%**，表示保费现金流经验调整全额计入
- **EA_ratio_iacf**：默认 **0%**，表示IACF经验调整不计入（差异通过其他机制处理）

## 8. 公式汇总表

| 调整类型 | 合同类型 | 公式 | 经验调整占比 |
|---------|---------|------|------------|
| 保费现金流 | 新增合同 | `Adj_Prem^New = [(New.F_end + New.C_actual) - (New.F_init + New.C_init)] × EA_ratio_prem` | 100% |
| 保费现金流 | 存量合同 | `Adj_Prem^Eff = [(Eff.F_end + Eff.C_actual) - (Eff.F_beg + Eff.C_year)] × EA_ratio_prem` | 100% |
| IACF | 新增合同 | `Adj_IACF^New = [(New.F_end^I + New.C_actual^I) - (New.F_init^I + New.C_init^I)] × EA_ratio_iacf` | 0% |
| IACF | 存量合同 | `Adj_IACF^Eff = [(Eff.F_end^I + Eff.C_actual^I) - (Eff.F_beg^I + Eff.C_year^I)] × EA_ratio_iacf` | 0% |
| 合计 | - | `Adj_Total = Adj_Prem + Adj_IACF` | - |

## 9. 注意事项

1. **PV原材料数据必须存在**：经验调整计算前，必须确保PV原材料数据已生成
2. **利率一致性**：所有现值项必须使用同一加权初始确认利率
3. **合同类型判定**：实施时需先判定合同类型，仅使用对应类型的项
4. **一次性缴费场景**：对于一次性缴费的保单，后续年度经验调整通常为0
5. **经验调整占比**：保费经验调整占比默认100%，IACF经验调整占比默认0%
